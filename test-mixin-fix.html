CustomPerm — Vérification du fix Mixin

L'AT n'a pas suffi (le JIT inline encore les valeurs des champs final). Mixin retire physiquement le final du bytecode au chargement de la classe — solution définitive.

Total : 0 Réussis : 0 Échoués : 0 En attente : 0

Résultats à coller dans le chat

Sélectionne tout (Ctrl+A), copie (Ctrl+C), et colle dans la conversation.

Préparation :
  1. Stoppe l'ancien serveur (stop).
  2. Relance avec .\gradlew.bat runServer — gradle re-build, compile la Mixin et l'intègre. Compte ~30 s.
  3. Si compile error sur org.spongepowered.asm.mixin.* → dis-le moi, j'ajoute une dépendance.
  4. Reconnecte le client sur 127.0.0.1.

Phase A — Compilation et chargement

CRITIQUEA.0 — Le build a réussi
Attendu : BUILD SUCCESSFUL (ou démarrage du serveur, ce qui implique build OK).
Si erreur : probablement un import Mixin non trouvé. Capture le message ci-dessous, je corrige le build.gradle.
CRITIQUEA.1 — Mixin chargée au démarrage

Dans les logs au démarrage, cherche une ligne qui mentionne le chargement de la Mixin :

... Mixing customperm.mixins.json ...
... ou ...
... [Mixin] Initialised Mixin FabricMixinBootstrap ... customperm.mixins.json ...
Le wording exact dépend de la version de Mixin. L'essentiel : pas d'erreur autour du fichier customperm.mixins.json.
Si tu vois Could not load mixins ou FAILED to apply mixin CommandNodeMixin → capture-le ci-dessous.
CRITIQUEA.2 — Pas de log "FAILED to stick"

Comme à la phase précédente : aucune ligne du type :

[CustomPerm] Requirement write FAILED to stick on /XXX (AT not applied?). Wrapper will not work.
Avec Mixin actif, ce log ne devrait plus apparaître. S'il apparaît quand même, le Mixin n'a pas pris effet sur cette commande.
A.3 — Backend LP + abonnement event toujours actifs
[CustomPerm] LuckPerms detected — using LuckPerms backend.
[CustomPerm] Subscribed to LuckPerms UserDataRecalculateEvent for live command tree resync.

Phase B — Le test décisif : /customperm debug

B.1 — Setup du scénario (non-op avec perm LP)
deop Dev
customperm command add gamemode
lp creategroup vip
lp group vip permission set customperm.command.gamemode true
lp user Dev parent add vip
Attendu : chaque commande répond Successfully.... La ligne [CustomPerm] LP user data recalculated for Dev apparaît à la fin.
CRITIQUEB.2 — La dernière ligne du debug doit être VERTE
customperm debug Dev gamemode
=== Debug for /gamemode (Dev) ===
  Command exists in dispatcher : true
  In granted-commands list    : true
  Source has op level 2       : false
  Source has op level 4       : false
  PermService says customperm.command.gamemode : true
  Logical decision (computed) : true
  Actual wrapper canUse()     : true     ← EN VERT, plus de MISMATCH
Si la dernière ligne est true en VERT → le Mixin a fait son boulot, le wrapper est actif.
Si encore false + MISMATCH → la Mixin n'a pas pris effet sur ce noeud. Note la sortie ci-dessous, j'investigue plus loin.
