CustomPerm — Procédure de test

Validation du mod sur NeoForge 1.21.1 avec LuckPerms en backend.

Total : 0 Réussis : 0 Échoués : 0 En attente : 0
Conventions : Console serveur = fenêtre PowerShell où tourne runServer, commandes sans /. Client en jeu = fenêtre Minecraft, commandes avec /.

Phase 0 — Vérification du chargement

0.1 — Vérifier le backend LuckPerms

Dans la console serveur, remonter dans les logs de démarrage et chercher la ligne suivante :

[CustomPerm] LuckPerms detected — using LuckPerms backend.
Attendu : la ligne est présente. Sinon, c'est le fallback interne qui est actif (à corriger).

Phase 1 — Baseline (Dev sans permission)

1.1 — S'assurer que Dev n'est pas op
deop Dev
op list
Attendu : sortie There are no operators ou liste ne contenant pas Dev.
1.2 — Tenter une commande sans permission
/gamemode survival
Attendu : Refus avec Unknown or incomplete command. Le rewriter a bien retiré la commande de l'arbre pour ce joueur.

Phase 2 — Création d'un grade et octroi d'une permission

2.1 — Créer le groupe vip et lui donner customperm.command.gamemode
lp creategroup vip
lp group vip permission set customperm.command.gamemode true
lp user Dev parent add vip
Attendu : chaque commande répond Successfully....
2.2 — Vérifier la permission via /customperm test
customperm test Dev customperm.command.gamemode
Attendu : [LuckPerms] Dev :: customperm.command.gamemode -> GRANTED en vert.
2.3 — Test critique : commande autorisée pour un non-op
/gamemode creative
Attendu : la commande passe, le mode passe en créatif. C'est la fonctionnalité principale du mod.

Phase 3 — Alias simple (1 commande)

3.1 — Créer l'alias /fly et donner la permission
customperm alias add fly gamemode spectator
lp group vip permission set customperm.alias.fly true
customperm alias list
Attendu : la liste affiche /fly (1 step).
3.2 — Exécuter l'alias en jeu
/fly
Attendu : passage en mode spectator. Si l'autocomplétion ne propose pas /fly, déconnecte/reconnecte (re-sync du command tree).

Phase 4 — Macro multi-step

4.1 — Créer un alias /heal avec 3 étapes
customperm alias add heal effect give @s minecraft:instant_health 10 100; effect give @s minecraft:saturation 1 100; say bien soigne
lp group vip permission set customperm.alias.heal true
customperm alias steps heal
Attendu : customperm alias steps heal affiche 3 lignes (#0, #1, #2).
4.2 — Exécuter la macro
/heal
Attendu : tu reçois l'effet de soin instantané, l'effet saturation, et le serveur dit [Dev] bien soigne dans le chat. Les 3 étapes s'enchaînent.

Phase 5 — Édition d'un alias en jeu

5.1 — Ajouter un step à un alias existant
customperm alias addstep heal effect give @s minecraft:strength 30 1
customperm alias steps heal
Attendu : 4 steps maintenant (#0, #1, #2, #3).
5.2 — Retirer un step par index
customperm alias removestep heal 2
customperm alias steps heal
Attendu : le step say bien soigne a disparu, les autres restent (renumérotés à partir de 0).

Phase 6 — Révocation et propagation immédiate

6.1 — Retirer le grade au joueur
lp user Dev parent remove vip
customperm test Dev customperm.command.gamemode
Attendu : [LuckPerms] Dev :: customperm.command.gamemode -> DENIED en rouge.
6.2 — Vérifier le refus immédiat côté client
/gamemode survival
Attendu : refus à nouveau (Unknown or incomplete command). La révocation s'est bien propagée sans déconnexion.

Phase 7 — Wildcard de permission

7.1 — Donner customperm.command.* au groupe
lp group vip permission set customperm.command.* true
lp user Dev parent add vip
Attendu : chaque commande répond Successfully....
7.2 — Tester plusieurs commandes vanilla en même temps
/give @s diamond 64
/effect give @s minecraft:speed 30 5
/time set day
Attendu : les 3 commandes passent. Le wildcard couvre toutes les commandes vanilla.

Phase 8 — Edge case : op préserve les droits vanilla

8.1 — Op le joueur et retirer toutes ses perms LP
op Dev
lp user Dev parent remove vip
customperm test Dev customperm.command.gamemode
Attendu : le test retourne DENIED (le test regarde uniquement le node LP, pas l'op-level — comportement par design).
8.2 — Vérifier qu'un op a quand même tout
/gamemode creative
Attendu : commande autorisée. Le wrapper requires respecte toujours l'op-level original (hasPermission(2)) en plus du node LP.

Checklist finale

  • Sans op + sans perm = refusé
  • Sans op + perm LP = autorisé
  • Révocation propagée immédiatement (pas de déconnexion requise)
  • Op niveau 4 = tout autorisé peu importe les nodes
  • Aliases simples fonctionnent
  • Aliases multi-step exécutent toutes les étapes dans l'ordre
  • Édition d'aliases en jeu (addstep / removestep) fonctionne
  • Wildcard customperm.command.* couvre toutes les commandes
  • /customperm test reflète l'état réel des perms LP
