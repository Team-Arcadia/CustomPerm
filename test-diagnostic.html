CustomPerm — Diagnostic des échecs

Procédure ciblée pour identifier la cause des échecs des phases 2.3, 3.2, 4.2, 6.2 et 7.2.

Total : 0 Réussis : 0 Échoués : 0 En attente : 0

Diagnostic à coller dans le chat

Sélectionne tout (Ctrl+A), copie (Ctrl+C), et colle dans la conversation.

Préparation : stoppe le serveur précédent (stop), supprime le monde si tu veux repartir propre (Remove-Item run\world -Recurse -Force), puis relance avec .\gradlew.bat runServer. Connecte le client sur 127.0.0.1.

Phase A — Vérification du chargement

A.1 — Backend LuckPerms détecté

Dans les logs de démarrage du serveur, cherche cette ligne :

[CustomPerm] LuckPerms detected — using LuckPerms backend.
A.2 — Abonnement à l'event LP actif

Toujours dans les logs de démarrage, cherche :

[CustomPerm] Subscribed to LuckPerms UserDataRecalculateEvent for live command tree resync.
Important : sans cette ligne, l'abonnement n'a pas pris et c'est la cause du non-resync. Si elle manque, regarde s'il y a un Could not subscribe LP events à la place.

Phase B — Setup du scénario qui échoue

B.1 — Mise en place propre

Dans la console serveur, exécute ces commandes une par une (rien ne doit échouer) :

deop Dev
customperm command add gamemode
customperm command list
Exposed commands: gamemode
lp creategroup vip
lp group vip permission set customperm.command.gamemode true
lp user Dev parent add vip
Attendu : chaque commande LP répond Successfully.... Le groupe vip peut déjà exister (la création échouera silencieusement, c'est OK).
B.2 — Capture du log LP recalculate

Juste après lp user Dev parent add vip à l'étape B.1, regarde si cette ligne s'affiche dans la console serveur (peut prendre 1-2 secondes) :

[CustomPerm] LP user data recalculated for Dev, resending command tree.
Important :
  • Si la ligne apparaît → l'event LP est reçu, on resend bien le command tree. Le bug est dans le wrapper lui-même. Continue à la phase C.
  • Si elle n'apparaît PAS → l'abonnement ne capte pas l'event, ou le joueur n'est pas connecté au moment de l'event. Note-le ci-dessous.

Phase C — Diagnostic du wrapper

C.1 — Lancer /customperm debug

Toujours dans la console serveur, lance le diagnostic :

customperm debug Dev gamemode

Tu vas voir un rapport ligne par ligne, du genre :

=== Debug for /gamemode (Dev) ===
  Command exists in dispatcher : true
  In granted-commands list    : true
  Source has op level 2       : false
  Source has op level 4       : false
  PermService says customperm.command.gamemode : true
  Logical decision (computed) : true
  Actual wrapper canUse()     : true
Le diagnostic clé est la dernière ligne :
  • Vert + même valeur que Logical decision → le wrapper fait son boulot, le souci est ailleurs (re-sync ou côté client).
  • Rouge avec un MISMATCH → la prédicat installée par le rewriter ne correspond pas à la logique attendue. Bug dans l'installation.
  • Command exists in dispatcher : false → le serveur ne connaît pas /gamemode à la racine. Anomalie majeure.

Phase D — Test côté client (commande directe)

D.1 — Forcer un tree frais (déco/reco)

Pour exclure définitivement un problème de re-sync, déconnecte le client et reconnecte-toi. Au join, le serveur envoie un command tree neuf calculé sur les perms actuelles.

Mode opératoire : dans le menu pause → "Save and quit to title", puis "Multiplayer" → reconnecte sur 127.0.0.1.
D.2 — Tester /gamemode après reconnect
/gamemode creative
Attendu : la commande passe, le mode passe en créatif. Si oui → c'était un problème de re-sync (résolu par la reconnexion). Si non → bug profond dans le wrapper (la phase C aura déjà donné le verdict).

Phase E — Re-test des aliases (avec le fix d'élévation)

E.1 — Créer un alias et donner la perm
customperm alias add fly gamemode spectator
lp group vip permission set customperm.alias.fly true
Attendu : les deux commandes répondent Successfully....
E.2 — Reconnecter le client

Déconnecte/reconnecte une nouvelle fois pour avoir l'alias /fly dans le tree.

E.3 — Tester /fly
/fly
Attendu : passage en mode spectator. Avec le fix, les steps de l'alias s'exécutent avec autorité d'op level 4 — le gamemode spectator interne passe quel que soit l'op-level réel du joueur.

Phase F — Macro multi-step

F.1 — Créer une macro et tester
customperm alias add heal effect give @s minecraft:instant_health 10 100; effect give @s minecraft:saturation 1 100; say bien soigne
lp group vip permission set customperm.alias.heal true

Reconnecte le client, puis :

/heal
Attendu : les 3 effets s'enchaînent (santé instantanée, saturation, message dans le chat).
